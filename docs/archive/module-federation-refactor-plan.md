# Module Federation Refactor Plan: Domain-Based Architecture

## Overview

Transform the monolith insurance app into a federated domain-based architecture using Module Federation, starting with the Documents domain (PDF-heavy) to achieve immediate bundle size reductions.

## Phase 0: Foundation (Week 1)

### Step 1: Assessment & Planning

1. **Current Bundle Analysis**

   ```bash
   ./scripts/analyze-bundle.sh
   # Output: Identify PDFME/TiTap/ExcelJS sizes
   ```

2. **Dependency Inventory**
   - Create dependency matrix: `docs/dependency-matrix.md`
   - Document which dependencies can be shared vs isolated

3. **Team Alignment**
   - Share refactor plan
   - Set performance targets
   - Establish rollback procedures

### Step 2: Module Federation Foundation

1. **Install Dependencies**

   ```bash
   npm install @module-federation/vite @module-federation/enhanced
   ```

2. **Create Federation Config Structure**

   ```bash
   mkdir -p federation/
   touch federation/
   ├── shared-deps.ts        # Shared dependency rules
   ├── types.ts             # Federation types
   ├── loader.ts            # Dynamic module loader
   └── error-boundary.tsx   # Federation error handling
   ```

3. **Update Vite Config**
   ```typescript
   // vite.config.federation.ts
   import { federation } from "@module-federation/vite";

   export default defineConfig({
     plugins: [
       federation({
         name: "portal",
         filename: "remoteEntry.js",
         exposes: {/* Portal shell */},
         remotes: {
           documents: "documents@https://documents.example.com/remoteEntry.js",
         },
         shared: sharedDepsConfig,
       }),
     ],
   });
   ```

## Rollback Plan

### Automatic Rollback Triggers

```yaml
rollback_triggers:
  performance:
    - module_load_time > 1000ms
    - navigation_slower_than_monolith: true
    - bundle_size_not_reduced: true

  stability:
    - error_rate > 2%
    - user_reports_degradation: true
    - critical_business_flow_broken: true

  operational:
    - deployment_fails > 3_times
    - team_cannot_debug_issues: true
    - monitoring_not_working: true
```

### Rollback Procedure

```bash
# Single command rollback
./scripts/rollback-federation.sh \
  --domain documents \
  --reason "performance_degradation" \
  --target-version previous-stable
```

## Risk Mitigation

### Technical Risks

1. **Module Federation Complexity**
   - **Mitigation**: Start with iframe fallback
   - **Monitoring**: Track module load times

2. **Cross-Domain State Issues**
   - **Mitigation**: Eventual consistency pattern
   - **Fallback**: Centralized state store (KV)

3. **Performance Degradation**
   - **Mitigation**: Preloading, caching, lazy loading
   - **Rollback**: Automatic if targets missed

### Organizational Risks

1. **Team Learning Curve**
   - **Mitigation**: Training sessions, pairing
   - **Documentation**: Comprehensive guides

2. **Deployment Coordination**
   - **Mitigation**: Automated deployment pipeline
   - **Tooling**: Single command deploy/rollback
